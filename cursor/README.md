# Vibeflow — Cursor Edition

Vibeflow configuration files for **Cursor**.

## What's included

```
cursor/
├── AGENTS.md                                     → repo root (appended if it already exists)
├── rules/
│   ├── vibeflow.mdc                              → .cursor/rules/ (always apply — guardrails)
│   └── vibeflow-architect.mdc                    → .cursor/rules/ (agent-decided — persona)
└── skills/
    ├── vibeflow-analyze/SKILL.md                 → .cursor/skills/ (deep-analyze codebase)
    ├── vibeflow-gen-spec/SKILL.md                → .cursor/skills/ (feature/PRD → spec)
    ├── vibeflow-implement/SKILL.md               → .cursor/skills/ (spec → code with guardrails; --loop)
    ├── vibeflow-prompt-pack/SKILL.md             → .cursor/skills/ (spec → prompt pack)
    ├── vibeflow-audit/SKILL.md                   → .cursor/skills/ (verify DoD + patterns)
    ├── vibeflow-discover/SKILL.md                → .cursor/skills/ (idea → PRD)
    ├── vibeflow-hotfix/SKILL.md                  → .cursor/skills/ (evidence → trace doc + fix + test)
    ├── vibeflow-quick/SKILL.md                   → .cursor/skills/ (fast-track ≤4 files)
    ├── vibeflow-teach/SKILL.md                   → .cursor/skills/ (update .vibeflow/ + --from import)
    └── vibeflow-stats/SKILL.md                   → .cursor/skills/ (audit statistics)
```

Every file uses the `vibeflow-` prefix to avoid clashing with the project's own files.

The installer also copies the execution loop kit into `.cursor/skills/vibeflow-implement/loop/`, downloading from the plugin (`plugins/vibeflow/skills/implement/loop/`, the single source) the files that the kit's `manifest.json` lists. An install made before CLI 0.17.0 does not have the kit: `npx setup-vibeflow@latest --cursor --force` installs it.

**Git:** By default, the installer (`npx setup-vibeflow@latest --cursor`) adds the installed files and the `.vibeflow/` folder (generated by analyze) to `.gitignore`, so they stay out of commits. If you want to track them in git, remove the "Vibeflow" block from `.gitignore`.

## Installation

At the root of the target repo:

```bash
npx setup-vibeflow@latest --cursor
```

The installer copies the files, creates the directories, and appends to `AGENTS.md` automatically.

## Usage

After installation, the skills are available in Cursor in two ways:

### Automatic invocation
Cursor detects which skill is relevant from the conversation's context. For example, if you say "I want to build a new feature", the `vibeflow-discover` skill may be activated automatically.

### Manual invocation (slash commands)
Type `/` in the Agent chat and search for the skill's name:

**Core:**
- `/vibeflow-analyze` — analyzes the codebase and generates `.vibeflow/` (flags: `--fresh`, `--scope`, `--interactive`, `--satellite`)
- `/vibeflow-gen-spec` — generates a spec with DoD, scope, anti-scope and applicable patterns
- `/vibeflow-implement` — implements the spec with guardrails (budget, DoD, patterns); `--loop` turns on the execution loop (below), `--no-loop` turns it off for one run
- `/vibeflow-prompt-pack` — generates a self-contained prompt pack with embedded patterns

**Secondary:**
- `/vibeflow-audit` — audits the implementation against DoD + patterns + tests + Critical Gate (PASS / PARTIAL / FAIL), from a review package of the diff (`--package`, `--base <ref>`); `--reaudit <commit>` checks a fix round; run by hand, it writes the probes and sabotages risk code only with `--probes`
- `/vibeflow-discover` — interactive dialogue (1–5 rounds) that turns a vague idea into a PRD
- `/vibeflow-hotfix` — observed defect with reproducible evidence: trace doc + fix + regression test written before the fix, in one call (resumes from a halted doc's path)

**Utilities:**
- `/vibeflow-quick` — fast-track for small tasks (≤4 files)
- `/vibeflow-teach` — updates `.vibeflow/` with corrections, conventions or decisions; `--from <url|path>` imports patterns from external repos
- `/vibeflow-stats` — audit statistics: rates, violations, trends, and the loop's numbers when there are ledgers in `.vibeflow/loop/`

### Execution loop (opt-in)

Off by default. With `/vibeflow-implement <spec> --loop` (or `loop: true` in `.vibeflow/loop/config.md`), the conversation becomes the orchestrator: the executor implements each part in a fresh session, the independent audit runs in another one, and there are at most two fix rounds. In Cursor, each fresh session is a chat you open with the one-line instruction the orchestrator writes ("Read `<briefing>` and follow it."). The loop ends in a pull request carrying the evidence when the remote is on GitHub (or GitHub Enterprise) and `gh auth status` is ok for its host; otherwise it pushes the branch and writes the body to `.vibeflow/reviews/<feature>-pr-body.md` for you to open the pull request or merge request by hand. It never merges, deploys, migrates a shared environment or reads production. The kit's scripts need Node.js 18 or newer (below that they exit with code 64). Details in [MANUAL.md](../MANUAL.md) (in Portuguese).

### Rules

The rules apply automatically:
- **vibeflow.mdc** (`alwaysApply: true`) — guardrails and an overview of the methodology, active in every conversation
- **vibeflow-architect.mdc** (`alwaysApply: false`) — the Architect persona, activated by Cursor when the conversation involves planning, specs or audits

## After installation

1. Use the `vibeflow-analyze` skill to generate the `.vibeflow/` folder.
2. Add `.vibeflow/` to git.
3. For new features, start with `vibeflow-discover`.

See [MANUAL.md](../MANUAL.md) (in Portuguese) for the full documentation, or visit [vibeflow.run](https://vibeflow.run) for the command docs and more about the plugin.
