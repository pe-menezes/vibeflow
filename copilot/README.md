# Vibeflow — Copilot Edition

Vibeflow configuration files for **GitHub Copilot**.

## What's included

```
copilot/
├── AGENTS.md                                     → repo root (appended if it already exists)
├── copilot-instructions.md                       → append snippet (optional)
└── github/                                       → maps to .github/ in the target repo
    ├── instructions/vibeflow/
    │   └── vibeflow.instructions.md              → full instructions
    ├── agents/
    │   └── vibeflow-architect.agent.md           → the Architect persona
    ├── prompts/
    │   ├── vibeflow-analyze.prompt.md        (core: deep-analyze codebase)
    │   ├── vibeflow-gen-spec.prompt.md       (core: feature/PRD → spec)
    │   ├── vibeflow-implement.prompt.md      (core: spec → code with guardrails)
    │   ├── vibeflow-audit.prompt.md          (secondary: verify DoD + patterns + gate)
    │   ├── vibeflow-discover.prompt.md       (secondary: idea → PRD)
    │   ├── vibeflow-prompt-pack.prompt.md    (secondary: spec → prompt pack)
    │   ├── vibeflow-hotfix.prompt.md         (secondary: evidence → trace doc + fix + test)
    │   ├── vibeflow-quick.prompt.md          (utility: fast-track ≤4 files)
    │   ├── vibeflow-teach.prompt.md          (utility: update .vibeflow/ + --from import)
    │   └── vibeflow-stats.prompt.md          (utility: audit statistics)
    └── skills/                                       → (reserved for future use)
```

The installer also copies the execution loop kit into `.github/vibeflow/loop/`, downloading from the plugin (`plugins/vibeflow/skills/implement/loop/`, the single source) the files that the kit's `manifest.json` lists, and the `.gitignore` block gains `.github/vibeflow/`. An install made before CLI 0.17.0 does not have the kit: `npx setup-vibeflow@latest --copilot --force` installs it.

Every file uses the `vibeflow-` prefix to avoid clashing with the project's own files.
Instructions live in a `vibeflow/` subfolder (Copilot supports subdirectories).

**Git:** By default, the installer (`npx setup-vibeflow@latest --copilot`) adds the installed files and the `.vibeflow/` folder (generated by analyze) to `.gitignore`, so they stay out of commits. If you want to track them in git, remove the "Vibeflow" block from `.gitignore`.

## Installation

At the root of the target repo:

```bash
npx setup-vibeflow@latest --copilot
```

The installer copies the files, creates the directories, and appends to `AGENTS.md` and `copilot-instructions.md` automatically.

## Execution loop (opt-in)

Off by default. With the `vibeflow-implement` prompt and `--loop` (or `loop: true` in `.vibeflow/loop/config.md`; `--no-loop` turns it off for one run), the chat becomes the orchestrator: the executor implements each part in a fresh session, the independent audit runs in another one, and there are at most two fix rounds, each re-audited on its own diff (`vibeflow-audit --reaudit <commit>`). In Copilot, each fresh session is a chat you open with the one-line instruction the orchestrator writes ("Read `<briefing>` and follow it."). The loop ends in a pull request carrying the evidence when the remote is on GitHub (or GitHub Enterprise) and `gh auth status` is ok for its host; otherwise it pushes the branch and writes the body to `.vibeflow/reviews/<feature>-pr-body.md` for you to open the pull request or merge request by hand. It never merges, deploys, migrates a shared environment or reads production. The kit's scripts need Node.js 18 or newer (below that they exit with code 64). Run by hand, `vibeflow-audit` writes the probes and sabotages risk code only with `--probes`. Details in [MANUAL.md](../MANUAL.md) (in Portuguese).

## After installation

1. Use the `vibeflow-analyze` prompt to generate the `.vibeflow/` folder.
2. Add `.vibeflow/` to git.
3. For new features, start with `vibeflow-discover`.

See [MANUAL.md](../MANUAL.md) (in Portuguese) for the full documentation, or visit [vibeflow.run](https://vibeflow.run) for the command docs and more about the plugin.
