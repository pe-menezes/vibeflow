# Contributing to Vibeflow

Thanks for your interest in contributing to Vibeflow! This document explains how to get involved.

## How to contribute

### Reporting bugs

Open an issue using the **Bug Report** template. Include:
- Edition affected (Codex, Claude Code, Hermes Agent, Copilot, Cursor, or CLI)
- Steps to reproduce
- Expected vs actual behavior

### Suggesting features

Open an issue using the **Feature Request** template. Describe the problem you're solving, not just the solution you want.

### Submitting code

1. **Fork** the repo and create a branch from `main`
2. Make your changes
3. Test your changes manually (see below)
4. Submit a **Pull Request** using the PR template

### What we accept

- Bug fixes (always welcome)
- Documentation improvements (always welcome)
- Prompt/methodology improvements (discuss in an issue first)
- New edition support (discuss in an issue first)
- CLI improvements (discuss in an issue first)

## Project structure

```
vibeflow/
├── .agents/plugins/       # Codex marketplace catalog
├── .claude-plugin/        # Claude marketplace catalog
├── plugins/vibeflow/      # Shared Claude + Codex + Hermes plugin and canonical skills
│   ├── .claude-plugin/plugin.json
│   ├── .codex-plugin/plugin.json
│   └── plugin.json        # Hermes Agent manifest (Agent Plugins v1)
├── copilot/               # GitHub Copilot edition
├── cursor/                # Cursor edition
├── cli/                   # npm installer for Copilot and Cursor
├── test/                  # dependency-free suite; test/audit/ holds audit probes
├── site/                  # Astro landing page (en, pt-br)
├── AGENTS.md              # Shared repository maintenance rules
├── MANUAL.md              # Full methodology docs (PT-BR)
├── CHANGELOG.md           # Version history
└── README.md              # Project overview (EN)
```

### Key concepts

- **5 agents, 1 methodology** — Codex, Claude Code, Hermes Agent, Copilot, and Cursor share the same pipeline.
- **Source of truth** — `plugins/vibeflow/skills/` feeds Claude, Codex and Hermes. Copilot prompts and Cursor skills mirror it in the same PR. The file mapping is in [`AGENTS.md`](AGENTS.md).
- **`.vibeflow/`** — The project knowledge base generated by `analyze`. Not committed by default.
- **The loop kit** lives once, inside the shared `implement` skill: `plugins/vibeflow/skills/implement/loop/` (principles, briefing templates, `orchestrator.md`, `pr-body.md`, `roles/`, `scripts/`). Claude and Codex ship it with the plugin, the `vibeflow-claude` mirror copies it with `skills/`, and the CLI installs it for Cursor and Copilot from the plugin path. Never copy it into `cursor/` or `copilot/`; edit it in place.
- **The kit's manifest** `loop/manifest.json` lists every file of the kit folder and nothing else, because the CLI installs exactly that list: a file added to or removed from the kit changes the manifest in the same commit (`test/cli-kit.test.mjs` fails otherwise), and the kit's `README.md` names it, with each script's exit codes (`test/loop-scripts.test.mjs`).
- **Permissions** — `test/permissions.test.mjs` lists the tools every skill (`allowed-tools`) and agent (`tools`) of `plugins/vibeflow/` declares, so changing one, or adding a skill or agent, means updating that list and adding a line under "Changed" in `CHANGELOG.md`.
- **Agent roles** live once in `loop/roles/executor.md` and `loop/roles/auditor.md`; the Claude agents `plugins/vibeflow/agents/executor.md` and `auditor.md` carry the same body after their front matter, byte for byte (tests compare them).

## Development

### Site (Astro)

```bash
cd site
npm install
npm run dev     # http://localhost:4321
npm run build   # production build
```

### CLI

```bash
cd cli
node index.js --copilot   # test copilot install
node index.js --cursor    # test cursor install
node index.js --codex     # verify Codex plugin instructions
node index.js --claude    # verify Claude plugin instructions
```

### Tests

The suite has no dependencies and is what the CI runs:

```bash
node --test test/*.test.mjs test/audit/*.test.mjs
```

`test/*.test.mjs` holds the contract and script tests; `test/audit/` holds the probes that independent audits of this repository left behind, as behavior tests, one file per subject (`<subject>.probes.test.mjs`). Each probe states its three pruning answers as comments right above its `test(` call (`Contract:`, `Breaks when:`, `Not covered by:`), so a reader can judge whether it still earns its place without any other document. A probe that reproduces a known open gap is marked `todo` with a plain description of the gap, so it runs and prints without failing the suite. The smoke harness (`node test/run-smoke.mjs`, see [`test/README.md`](test/README.md)) calls the real `claude` CLI and costs money; it is not part of the suite.

### Prompts / Commands / Skills

These are Markdown files. Edit directly and test in the respective agent:
- **Copilot**: `copilot/github/prompts/*.prompt.md`
- **Cursor**: `cursor/skills/*/SKILL.md`
- **Claude Code + Codex**: `plugins/vibeflow/skills/*/SKILL.md`

## Code style

- **Commits**: Use [Conventional Commits](https://www.conventionalcommits.org/) — `feat:`, `fix:`, `docs:`, `chore:`
- **Language**: Code and commits in English. Documentation can be bilingual (EN + PT-BR).
- **Prompts**: state the rule, not the volume. Write for a frontier model that
  already knows its tools: no caps as emphasis (`MANDATORY`, `NEVER`, `Do NOT`),
  no `⚠️`, no restating what the model knows, one instruction in one place, and
  judgment where a script would only guess. Guardrails stay literal — budget
  values, DoD limits, the Critical Gate catalog, marker contracts, artifact
  paths. The normative guide, with the delete-list, the keep-list and
  before/after pairs from this repo, is
  [`proposals/unhobbling-style.md`](proposals/unhobbling-style.md).

## Sync workflow

Changes to the universal plugin are auto-synced to the [vibeflow-claude](https://github.com/pe-menezes/vibeflow-claude) compatibility repository via GitHub Actions. Do not update that mirror manually.
