# Contributing to Vibeflow

Thanks for your interest in contributing to Vibeflow! This document explains how to get involved.

## How to contribute

### Reporting bugs

Open an issue using the **Bug Report** template. Include:
- Edition affected (Codex, Claude Code, Copilot, Cursor, or CLI)
- Steps to reproduce
- Expected vs actual behavior

### Suggesting features

Open an issue using the **Feature Request** template. Describe the problem you're solving, not just the solution you want.

### Submitting code

1. **Fork** the repo and create a branch from `main`
2. Make your changes
3. Test your changes manually (see below)
4. Submit a **Pull Request** using the PR template

### What we accept

- Bug fixes (always welcome)
- Documentation improvements (always welcome)
- Prompt/methodology improvements (discuss in an issue first)
- New edition support (discuss in an issue first)
- CLI improvements (discuss in an issue first)

## Project structure

```
vibeflow/
├── .agents/plugins/       # Codex marketplace catalog
├── .claude-plugin/        # Claude marketplace catalog
├── plugins/vibeflow/      # Shared Claude + Codex plugin and canonical skills
├── copilot/               # GitHub Copilot edition
├── cursor/                # Cursor edition
├── cli/                   # npm installer for Copilot and Cursor
├── site/                  # Astro landing page (en, pt-br)
├── AGENTS.md              # Shared repository maintenance rules
├── MANUAL.md              # Full methodology docs (PT-BR)
├── CHANGELOG.md           # Version history
└── README.md              # Project overview (EN)
```

### Key concepts

- **4 agents, 1 methodology** — Codex, Claude Code, Copilot, and Cursor share the same pipeline.
- **Source of truth** — `plugins/vibeflow/skills/` feeds both Claude and Codex. Copilot prompts and Cursor skills mirror it in the same PR. The file mapping is in [`AGENTS.md`](AGENTS.md).
- **`.vibeflow/`** — The project knowledge base generated by `analyze`. Not committed by default.

## Development

### Site (Astro)

```bash
cd site
npm install
npm run dev     # http://localhost:4321
npm run build   # production build
```

### CLI

```bash
cd cli
node index.js --copilot   # test copilot install
node index.js --cursor    # test cursor install
node index.js --codex     # verify Codex plugin instructions
node index.js --claude    # verify Claude plugin instructions
```

### Prompts / Commands / Skills

These are Markdown files. Edit directly and test in the respective agent:
- **Copilot**: `copilot/github/prompts/*.prompt.md`
- **Cursor**: `cursor/skills/*/SKILL.md`
- **Claude Code + Codex**: `plugins/vibeflow/skills/*/SKILL.md`

## Code style

- **Commits**: Use [Conventional Commits](https://www.conventionalcommits.org/) — `feat:`, `fix:`, `docs:`, `chore:`
- **Language**: Code and commits in English. Documentation can be bilingual (EN + PT-BR).
- **Prompts**: state the rule, not the volume. Write for a frontier model that
  already knows its tools: no caps as emphasis (`MANDATORY`, `NEVER`, `Do NOT`),
  no `⚠️`, no restating what the model knows, one instruction in one place, and
  judgment where a script would only guess. Guardrails stay literal — budget
  values, DoD limits, the Critical Gate catalog, marker contracts, artifact
  paths. The normative guide, with the delete-list, the keep-list and
  before/after pairs from this repo, is
  [`proposals/unhobbling-style.md`](proposals/unhobbling-style.md).

## Sync workflow

Changes to the universal plugin are auto-synced to the [vibeflow-claude](https://github.com/pe-menezes/vibeflow-claude) compatibility repository via GitHub Actions. Do not update that mirror manually.
